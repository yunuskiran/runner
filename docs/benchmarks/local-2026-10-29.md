# Local engine comparison

Exploratory measurements of in-process jobs on one shared development machine. No production sizing or universal winner claim. Business latency excludes framework finalization; throughput waits for durable drain. Completed SQL requests are server RPC + batch events, not EF command counts. Statement event classes overlap framework/request boundaries and are reported separately. Long-poll requests still running at the end are shown as active requests.

| responsive | quartz | 1 | 58.03 | 870.0 | 10.519 | 0.0 | 27.55 | 2.0 |
| responsive | runner | 1 | 59.59 | 1503.3 | 8.121 | 0.0 | 20.73 | 2.0 |

Defaults and responsive profiles have different discovery latencies: do not treat cross-profile throughput as pure execution speed. Runner includes its ordinary attempt/lifecycle journal; Hangfire includes its ordinary state history; Quartz uses default history settings and removes completed one-shot triggers. None includes HTTP, auth/audit middleware, or per-job process startup. Common result recording goes to a separate database excluded from engine DB counters; its cost remains in wall time. All schemas are fresh and warm-up/settling run before measurement. Read the raw effective settings and methodology before drawing conclusions.
